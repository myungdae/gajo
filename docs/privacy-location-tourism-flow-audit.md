# 개인정보·위치정보·관광 흐름 분석 감사

## 설계 원칙

EXKOVIA는 사람을 추적하는 플랫폼이 아니라 관광의 연결 성과를 분석하는 플랫폼으로 설계한다. 개인별 여행 동선이나 이름·전화번호와 결합된 동선을 파트너 또는 지자체에 제공하지 않는다. GPS는 방문자가 요청한 위치 기반 기능에만 사용하며 백그라운드 추적은 허용하지 않는다.

이번 작업의 완료 범위는 **현행 데이터 흐름 감사 및 보호 원칙 문서화 완료**이다. 개인정보 보호형 집계 분석의 구현 완료나 법률 준수를 의미하지 않는다.

## 현재 구현된 보호 경계

- 브라우저 위치는 `getCurrentPosition`으로만 요청한다. `watchPosition`과 백그라운드 위치 수집 코드는 없다. Nearby는 5분, 일반 여행 문맥은 30분 freshness를 적용한다.
- 확인된 좌표와 위치 문맥은 지역별 `TripSession`의 `locationContext`로 `localStorage`에 저장되고 쓰기 실패 때 `sessionStorage`를 사용한다. Portal 진입은 TripSession이나 GPS를 만들지 않는다.
- 추천 요청에는 필요한 현재 좌표와 지역 ID가 서버로 전송될 수 있다. Nearby 요청도 좌표·반경·분류·지역 ID를 서버에 보내며, 서버의 공급자 검색에 사용된다.
- Pilot analytics는 고정 event type, region ID, 익명 TripSession ID와 서버 allowlist에 포함된 scalar metadata만 MongoDB에 저장한다. 서버는 임의 `source`·`intent`, 원문·검색어·좌표·TripSession 식별자 키, 중첩 객체·배열 및 prototype pollution 키가 포함된 이벤트를 거부한다.
- QR 유입은 partner slug와 entry source를 사용한다. 추천, 정보 조회, 지도, 전화, 내비, 저장/일정 추가 이벤트가 존재한다. 방문확인 이벤트는 현재 analytics allowlist에서 확인되지 않았다.
- EXKO 링크는 고정 allowlist URL이며 방문자 좌표·TripSession ID·검색어 query를 덧붙이지 않는다.
- `GET /api/analytics/summary`는 기존 `AdminTokenGuard`의 `x-admin-token` 서버 인증 뒤에서 집계값만 반환한다. 지역 Admin 화면도 기존 관리자 토큰을 같은 header로 전달한다. 응답에는 개별 이벤트, 식별자, 좌표, 원문 또는 개인 동선 목록이 없다. 다만 서버 저장 레코드는 익명 TripSession ID로 이벤트를 연결할 수 있다.

## 확인된 미해결 위험

- PilotEvent의 timestamps는 존재하지만 보유기간·TTL·사용자 삭제 정책은 코드에 없다.
- 최소 표본 억제 기준이 없다. 현재 summary는 관리자 인증 뒤에 있지만 파트너·지자체용 외부 통계 공개 전에는 별도의 공개 권한과 최소 표본 정책이 필요하다.
- 익명 TripSession ID로 서버 이벤트를 연결할 수 있다. 이 식별자의 필요성·보유 범위·삭제 절차가 정해져 있지 않다.
- agent execution log에는 operation/task 상태가 저장된다. 운영 로그에 자유 입력 또는 좌표가 남는지 모든 배포 환경의 로그 설정까지 코드만으로 보증할 수 없다.

## 파트너·지자체 분석 공개 전 필수 결정사항

현재 관리자용 summary와 향후 파트너·지자체용 외부 통계를 구분하고, 외부 통계의 접근 주체와 권한, 합의된 최소 표본 기준, 익명 TripSession ID의 필요성, 보유기간, 삭제·내보내기, 로그 마스킹을 먼저 정해야 한다. 합의 전에는 개인 단위 기록이나 소표본 집계를 파트너·지자체에 공개하지 않는다. 이번 변경은 임의 TTL, 최소 표본 수, migration, 기존 데이터 삭제 또는 새로운 analytics 수집을 추가하지 않았다.

파트너 분석은 향후 QR 유입·추천·조회·지도·전화·내비·방문확인 같은 집계 통계로만 제공해야 하며, 합의된 최소 표본보다 작은 결과는 숨겨야 한다. 개인 이벤트 조회 API나 상세 이동경로 제공 기능은 추가하지 않는다.

## 법률·개인정보 전문가 검토가 필요한 사항

계정·쿠폰·QR 방문확인을 위치 또는 이동 흐름과 결합하는 정식 서비스 전에는 처리 목적과 법적 근거, 동의, 고지, 보유·파기, 정보주체 권리, 외부 제공·처리위탁, 위치정보 관련 의무를 별도로 검토해야 한다. 이 문서는 법률 준수를 단정하지 않는다.
